# GitHub 배포용 교육 HTML 제작 표준 v01

## 0. 상위 규칙 및 적용 범위

이 문서는 교육용 HTML의 **통합 표준**입니다. 이전 범용 웹 표준의 보안·접근성·테마·코드 표현 규칙은 10절로 이관했습니다. 교육용 페이지는 책장 사진·2열 좌측 탐색·밝은 테마 중심 규격을 우선합니다. 일반 웹·대시보드에는 교육용 시각 규격을 강제하지 않습니다.

## 1. 목적

같은 교육 브랜드 아래 여러 GitHub 저장소의 교육자료를 **구조화 · 체계화 · 순서화**하여 동일한 화면 구성으로 제공합니다. `ai-agent-engineering`의 2026-11-11 게시본을 기준 디자인으로 삼습니다.

## 2. 시각 규칙

| 항목 | 표준 |
|---|---|
| 상단 이미지 | 원본 교재 책장 사진 `hero-bookshelf.jpg` 하나로 통일, 흐림 없음 |
| 이미지 크기 | 1800×380px 원본, 화면 전체 너비에 `cover` 적용 |
| 헤더 높이 | 콘텐츠에 맞춰 약 160~220px, 과도한 상단 여백 금지 |
| 이미지 가독성 | 좌측 검정 반투명 그라데이션, 이미지 색상은 보존 |
| 페이지 바탕 | `#F1F2EE` |
| 본문 카드 | 흰색 `#FFFFFF`, 얇은 회색 테두리 |
| 주요 글자 | `#15171C` |
| 강조 | 보라색 `#4635B1` |
| 헤더 강조 | 노랑 `#FFD24A` |
| 글꼴 | IBM Plex Sans KR + IBM Plex Mono (미접속 시 시스템 글꼴) |
| 본문 폭 | 최대 1180px, 본문 좌측에 목차 240px |
| 모바일 | 폭 860px 이하에서 서랍형 탐색 메뉴 |

## 3. 페이지 구조

- `index.html` — 사이트 소개, 전체 학습 테크트리, 장별 바로가기, 학습·검증 원칙
- `ch01_기술주제_v01.html` — 배경 개념, 전체 실습 흐름, 환경 확인, 단계별 코드, 실행 결과, 검증
- 각 절은 `##` 제목에서 자동 분리하고 00, 01, 02 순서로 번호를 붙입니다.
- 내용이 없는 절이나 장식용 섹션은 넣지 않습니다.
- 코드 블록에는 사용 언어를 명시하고, 실제 예상 출력은 코드와 별도로 표시합니다.
- RTL·하드웨어 실습에서는 소스/신호 이름과 구조도 표기를 일치시킵니다.

## 4. 탐색·접근성

1. 좌측 고정 메뉴: 전체 장 → 현재 페이지의 절 순서
2. 현재 장 강조, 현재 절 스크롤 위치 강조
3. 모바일에서는 `☰ 장·목차` 버튼으로 슬라이딩 메뉴
4. 메뉴 바깥 클릭·Escape 키로 닫기
5. 이전/다음 장 이동 버튼과 INDEX 복귀
6. 모든 링크와 버튼은 키보드 접근 지원
7. 코드 복사 버튼은 브라우저 권한에 따라 작동하며, 불가 시 오류 표시

## 5. 콘텐츠 작성 원칙

1. 개념은 필요성 → 구조 → 과정 → 결과 순으로 설명합니다.
2. Ubuntu 명령은 기능 설명과 순서를 함께 씁니다.
3. 완결된 실습을 우선하며 장황한 제작 메모·사족은 배제합니다.
4. 코드 → 예상 출력 → 핵심 코드 풀이 → 검증 순서가 바람직합니다.
5. 정상 기존 코드는 그대로 유지하고 필수 수정과 선택 개선을 구분합니다.
6. 공식 출처, 교육용 예시, 실제 검증 결과를 구분합니다.
7. 읽기 전용 분석을 우선하고, 원본 파일 변경·외부 게시·파괴적 명령은 승인합니다.

## 6. 파일명·버전 규칙

- 장별: `ch01_topic_v01.html` → `ch01_topic_v02.html`
- INDEX: GitHub Pages 진입점인 `index.html`을 유지하며, `course.json`의 사이트 버전을 `v02`로 올립니다.
- 빌드 시 `dist/`에서 구버전 파일을 삭제합니다.
- 다른 저장소의 원본 파일과 Git 히스토리를 임의 삭제하지 않습니다.
- 저장소별 학습 내용은 별도 유지하고 공통 디자인·탐색 로직만 재사용합니다.

## 7. 배포 점검

- [ ] INDEX → 장별 링크 전부 정상
- [ ] 좌측 장 이동, 절 이동, 이전/다음 장 이동 정상
- [ ] 상단 사진·헤더 높이·모바일 표시 일치
- [ ] 코드 복사·Escape 닫기 정상
- [ ] HTML·Python 등 코드 문법 검사
- [ ] 실행 여부를 검증한 테스트 로그 보유 여부 표시
- [ ] 계정명·토큰·이메일·내부 경로·민감한 이미지 미노출
- [ ] 버전 충돌·이전 파일 잔존 없음
- [ ] GitHub Pages 실제 배포 확인

## 8. 기존 저장소 변환 방법

1. 기존 저장소의 문서·이미지·장 목록을 먼저 백업합니다.
2. `course.json`에 기존 장 목록과 파일명을 등록합니다.
3. 각 장의 본문을 `content/*.md`로 옮기되 코드·이미지·절 순서를 임의 변경하지 않습니다.
4. `python build.py`로 `dist/`에 미리보기 생성합니다.
5. 기능·배포 검증 후 각 저장소에 게시합니다.

**현재 템플릿은 Markdown의 문단·표·코드블록을 지원합니다.** 기존 복잡한 SVG·이미지·인터랙티브 HTML을 그대로 변환하는 완전 자동 이식 기능은 제공하지 않으므로 해당 자료는 별도 호환성 확인이 필요합니다.

## 9. 외부 저장소 참조

새 교재 저장소의 `README.md` 및 코딩 에이전트용 `AGENTS.md`에 중앙 규칙 링크를 명시합니다. **링크만으로 HTML 디자인은 자동 변경되지 않으며** 실제 템플릿 복사·빌드·검증이 필요합니다. 구체적인 문구와 절차는 [INTEGRATION.md](INTEGRATION.md)를 따릅니다.


## 10. 범용 웹페이지 공통 규칙 (기존 YJWS 통합)

### 10.1 화면 목적과 레이아웃
- 기술 교재, 연구보고서, 프로젝트 소개, 대시보드, 일반 문서, 기술문서 포털에 적용합니다. **교육용 페이지의 2~4절 디자인이 교육용 기준**이며 일반 웹·대시보드에 같은 책장 배너를 강제하지 않습니다.
- 일반 웹은 목적에 따라 1열/2열/3열을 선택하며, 기술문서형은 좌측 전체 목차 + 중앙 본문 + 우측 현재 문서 목차를 선택할 수 있습니다. 패널은 접기 기능을 지원합니다.
- 과도한 최대 폭 제한을 피하고 코드·표·구조도에 가용 너비를 제공합니다. 설명 문단은 읽기 쉬운 줄 길이를 유지합니다.
- 화면 폭 1920·1366·1024·768·390·320px에서 가로 넘침 및 목차 동작을 확인합니다.

### 10.2 테마·인쇄
- 교육용 HTML은 본 표준의 밝은 색상을 유지합니다. 일반 웹/대시보드에서 필요한 경우 사용자가 다크 테마를 선택하고 브라우저에 선택을 보존하도록 합니다.
- 다크 테마 적용 시 코드·표·SVG·텍스트 대비를 모두 확인합니다. 인쇄 시에는 밝은 배경을 사용합니다. 저장 기능이 제한되어도 본문은 정상 동작해야 합니다.
- 선택적으로 Alt + T 전환 단축키를 제공하되 키보드 사용성을 해치지 않아야 합니다.

### 10.3 코드·도식·원본 보존
- 기존 저장소의 검증된 CSS를 우선 검토합니다. 참고: [Pytorch_Learning CSS](https://github.com/Yuul-Jung/Pytorch_Learning/blob/main/docs/llm-finetuning/assets/style.css). 정상적인 디자인과 기존 코드를 불필요하게 재작성하지 않습니다.
- 코드 박스는 **파일명·언어·검증 상태**를 표시하고 `white-space: pre`와 박스 내부 가로 스크롤을 우선합니다. 복사 버튼은 실제 소스만 복사해야 합니다. 원본 소스를 이미지로 대체하지 않습니다.
- 실습 자료는 전체 코드 → 실제/예상 실행 결과 구분 → 실제 코드 구문 중심 해설을 권장합니다.
- 구조도의 모듈·함수·신호·상태명은 원본 코드와 일치시킵니다. SVG 연결선과 글자 겹침을 검증하며 필요시 Mermaid 원본을 별도로 보관합니다.
- 유지보수용 CSS·JS는 읽기 쉬운 들여쓰기와 주석을 유지하고, 배포용 압축본은 따로 만듭니다.
- 소스코드는 [공통 코딩 표준](../../common/code-style-rules.md), 구조도는 [플로우차트 표준](../../common/flowchart-rules.md)을 따릅니다.

### 10.4 접근성·보안·검증
- 키보드 조작, 제목 계층, 본문 바로가기, 초점 표시, 이미지 대체 텍스트, 대비, `prefers-reduced-motion`을 고려합니다. 메뉴·복사·테마 버튼은 실제로 동작해야 합니다.
- JavaScript 미사용 환경에서도 핵심 본문이 읽혀야 합니다. 외부 의존성을 불필요하게 늘리지 않습니다.
- 배포 전 계정·비밀번호·토큰·이메일·로컬 경로·비공개 문서·화면 캡처·이미지 메타데이터의 노출을 점검합니다.
- 적대적 검증: 기술 정합성, 화면 폭·반응형, 테마, SVG·코드, 링크·탐색, 접근성, 개인정보, 재현 가능한 실행 증거. 판정은 **통과/실패/미검증/해당 없음**으로 구분합니다.
- 제작 순서: 원본 확인 → 페이지 유형 선택 → 표준 적용 → 기술 내용 작성 → 코드·도식 검증 → 화면 점검 → 보안·접근성 점검 → 배포.
