## 1. 규칙 운영 체계

| 구분 | 내용 | 변경 정책 |
|------|------|----------|
| **① 기본 규칙** | HTML 학습안내서 작성 규칙 | 확정·고정 — 임의 변경 금지 |
| **② 추가 규칙** | 코드 작성·AI 개발·VS Code 환경 규칙 | 점진적 개선 — 검증 후 반영 |

- ①과 ②가 충돌하면 **①을 우선**합니다.
- ②에서 검증된 개선이라도 ①에 자동 편입하지 않습니다.

## 3. 적용 우선순위

1. 보안·개인정보 보호 및 실제 검증된 기술 사실
2. [HTML 학습안내서 작성 표준](web/education-html/STANDARD.md) (① 기본 규칙)
3. [코드 작성·개발 규칙](code/code-development-rules.md) (② 추가 규칙)
4. 공통 코드 스타일·플로우차트 규칙
5. 분야별 전용 규칙 (FPGA/SoC 등)

**실제 코드·UART 명령·레지스터 맵 등 기술적 사실은 디자인 규칙 때문에 변경하지 않습니다.**

---

## 4. 작성·검증 절차

원본 확인 → 구조 설계 → 콘텐츠 작성 → 적대적 검증 → 화면·실행 확인 → 접근성·보안 검사 → 공개

실행하지 않은 검증은 **미검증**으로 표시하며, 성공했다고 단정하지 않습니다.

---

## 5. 공개 저장소 주의사항

비밀번호·토큰·이메일·개인정보·비공개 경로·내부 문서·검토하지 않은 화면 캡처는 공개하지 않습니다.

## 6. 언어 및 변경 관리

- 모든 설명·제목·표·검증 보고는 **한글**로 작성합니다.
- 영문 기술 용어는 처음 사용할 때 한글 의미를 병기합니다.
- 코드 문법과 파일 경로는 기술적 호환성을 위해 원문 표기를 유지합니다.
- 변경 이력을 남기고, 기존 정상 자료를 불필요하게 전면 재작성하지 않습니다.
